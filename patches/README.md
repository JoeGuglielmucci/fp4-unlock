# patches/

These four patches are the shipped change. They apply to a clean checkout of upstream ggml-org/llama.cpp at the
commit in `docs/PINNED_COMMIT`; `scripts/fetch-llama.sh` does that into `third_party/llama.cpp` (gitignored) and
`scripts/build.sh` calls it. They are generated by `scripts/regen-patches.sh` (`git diff <pinned> -- <files>` on
the working tree, new files via intent-to-add), never hand-edited. Verified on 2026-10-27: a fresh clone + apply
reproduces the development tree byte for byte, builds, and passes the tests below.

| # | files | what | upstream status |
|---|---|---|---|
| 0001 | `src/llama-model.cpp` | Skip the NextN (MTP head) NVFP4 scale tensors when MTP is off, so an MTP GGUF loads with `--mtp` absent ("expected 1101, got 1079" on the 35B-A3B). Bug fix, regression visible on the pinned commit. | PR candidate (owner) |
| 0002 | `tests/test-backend-ops.cpp` | `MUL_MAT_BATCH` / `FA_BATCH` batch-invariance tests (column 0 of an n-column result vs the n = 1 result, bitwise), `MUL_MAT_W4A8` / `MUL_MAT_W4A4` eval groups, and the `FP4_UNLOCK_PERF_SHAPES=1` perf shapes (27B FFN shapes at M = 1..8). | overlaps #28488; PR candidate after that lands |
| 0003 | `ggml/src/ggml-cuda/fp4-unlock.cuh`, `fattn-common.cuh`, `fattn.cu`, `fattn-mma-f16.cuh` | Invariant mode (`FP4_UNLOCK_INVARIANT=1`): pins the flash-attention kernel choice and the stream-k / parallel_blocks split so an M <= 8 batch reduces in the M = 1 order. Opt-in; costs are in `docs/FINDINGS.md` ("What the pins cost"). | not submitted; compare Apoze 6263445 |
| 0004 | `ggml/src/ggml-cuda/fp4-smallm.cu`, `fp4-smallm.cuh`, `mmvq.cu` | The small-M NVFP4 kernel (block-scaled FP4 MMA, residual activation terms, batch-invariant in M = 1..8) and its dispatch from `ggml_cuda_mul_mat_vec_q`; `mmvq.cu` also carries the invariant-mode MMVQ rule (k-quants stay on MMVQ to M = 8, warp count pinned under `-DFP4_UNLOCK_INVARIANT_MMVQ`) and the Phase 1.5 `FP4_UNLOCK_SMALLM` experiment knob. | PR 3 candidate (owner), after an issue to gauge interest |

Build flags (see `scripts/build.sh`): `-DFP4_UNLOCK_INVARIANT_MMVQ` enables the pinned MMVQ warp count that
invariant mode relies on; `-DGGML_CUDA_FP4_SMALLM` makes the kernel the default (`FP4_UNLOCK_KERNEL=1`); without it
the kernel is compiled but off unless `FP4_UNLOCK_KERNEL=1` is set. No CMake changes are needed (`ggml-cuda` globs
`*.cu`). The `build-p3` tree uses both flags and is what every "after" number was measured on.

Runtime switches (all optional): `FP4_UNLOCK_KERNEL` 0 = upstream MMVQ, 1 = FP4 MMA kernel (default in p3), 2 =
int8 MMA fallback, 3 = in-block-quantization variant (A/B only); `FP4_UNLOCK_T` residual activation terms 1..4
(default 2; 1 = W4A4); `FP4_UNLOCK_MIN_M` smallest batch sent to the kernel (default 5; 1 under
`FP4_UNLOCK_INVARIANT=1`); `FP4_UNLOCK_INVARIANT=1` bitwise spec = greedy mode.
