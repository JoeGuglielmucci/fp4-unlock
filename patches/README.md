# patches/

These four patches are the whole change. They apply to a clean checkout of upstream ggml-org/llama.cpp at the
commit in `docs/PINNED_COMMIT`; `scripts/fetch-llama.sh` does that into `third_party/llama.cpp` (gitignored) and
`scripts/build.sh` calls it. They are generated by `scripts/regen-patches.sh` (`git diff <pinned> -- <files>` on
the working tree, new files via intent-to-add), never hand-edited. A fresh clone plus `git apply` reproduces the
tree the README numbers were measured on, builds, and passes the tests listed in the README.

| # | files | what |
|---|---|---|
| 0001 | `src/llama-model.cpp` | Skip the NextN (MTP head) NVFP4 scale tensors when MTP is off, so an MTP GGUF loads with `--mtp` absent ("expected 1101, got 1079" on Qwen3.6-35B-A3B NVFP4-MTP). Bug fix, visible on the pinned commit. |
| 0002 | `tests/test-backend-ops.cpp` | `MUL_MAT_BATCH` / `FA_BATCH` batch-invariance tests (column 0 of an n-column result against the n = 1 result, bitwise), `MUL_MAT_W4A8` / `MUL_MAT_W4A4` eval groups, and the `FP4_UNLOCK_PERF_SHAPES=1` perf shapes (the 27B FFN shapes at M = 1..8). |
| 0003 | `ggml/src/ggml-cuda/fp4-unlock.cuh`, `fattn-common.cuh`, `fattn.cu`, `fattn-mma-f16.cuh` | Invariant mode (`FP4_UNLOCK_INVARIANT=1`): pins the flash-attention kernel choice and the stream-k / parallel-blocks split so a batch of up to 8 query columns reduces in the M = 1 order. `fp4-unlock.cuh` holds the switch and prints a warning when the build lacks the MMVQ pin below. |
| 0004 | `ggml/src/ggml-cuda/fp4-smallm.cu`, `fp4-smallm.cuh`, `mmvq.cu` | The small-M NVFP4 kernel (block-scaled FP4 MMA, residual activation terms, reduction order independent of M) and its dispatch from `ggml_cuda_mul_mat_vec_q` for M in [`FP4_UNLOCK_MIN_M`, 8] on compute 12.x. `mmvq.cu` also carries the invariant-mode MMVQ rule (k-quant types stay on MMVQ through M = 8; warp count pinned under `-DFP4_UNLOCK_INVARIANT_MMVQ`) and the `FP4_UNLOCK_SMALLM` routing experiment that preceded the kernel. |

Compile flags (set by `scripts/build.sh`; no CMake changes are needed because `ggml-cuda` globs `*.cu`):

| flag | build target | effect |
|---|---|---|
| `-DGGML_CUDA_FP4_SMALLM` | `after` (default, `build/`) and `invariant` | the kernel is on by default (`FP4_UNLOCK_KERNEL=1`); without the flag it is compiled but off unless `FP4_UNLOCK_KERNEL=1` is set |
| `-DFP4_UNLOCK_INVARIANT_MMVQ` | `invariant` only (`build-invariant/`) | pins the MMVQ warp count, which full bitwise invariance under `FP4_UNLOCK_INVARIANT=1` needs; costs 7-8 % on the verify rows, so it is a separate build rather than a runtime switch |

Runtime switches are listed in the README (`FP4_UNLOCK_KERNEL`, `FP4_UNLOCK_T`, `FP4_UNLOCK_MIN_M`,
`FP4_UNLOCK_INVARIANT`). `FP4_UNLOCK_NWARPS` and `FP4_UNLOCK_KSPLIT` are tuning overrides for the kernel's warp
count and split-K count and are not needed in normal use.
