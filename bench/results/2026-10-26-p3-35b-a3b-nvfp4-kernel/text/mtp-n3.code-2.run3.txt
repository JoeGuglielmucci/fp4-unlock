   ```python
   def merge_intervals(intervals):
       if not intervals:
           return intervals
       intervals.sort(key=lambda x: x[1])
       merged = [intervals[0]]
       for current in intervals:
           last = merged[-1]
           if current[0] < last[1]:
               last[1] = max(last[1], current[1])
           else:
               merged.append(current)
       return merged
   ```

This means the first interval is processed twice (once when initializing `merged`, and again in the loop). Actually, wait: `merged = [intervals[0]]` takes the first element after sorting. Then the loop iterates over *all* elements in `intervals`, including the first one. So the first interval is compared against itself, which might not cause a crash but is logically redundant and could cause issues if not handled carefully. More importantly, the standard algorithm iterates from the second element: `for current in intervals[1:]`.
