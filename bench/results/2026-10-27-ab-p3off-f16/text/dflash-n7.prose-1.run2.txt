"Speculative decoding speeds up large language model inference by using a small, fast draft model to propose several future tokens before the large target model is run. The draft model generates a short candidate sequence, often greedily or with a simple sampling policy, because it is much cheaper to evaluate. The target model then processes the original prompt plus the proposed tokens in a single forward pass and computes its own probabilities for every position in that sequence. This lets the target model verify multiple candidate tokens at once instead of generating them one by one, which is the usual bottleneck in autoregressive decoding.

The key correctness property is that the final output distribution can be made identical to ordinary target-model decoding. For each proposed token, the algorithm compares the draft probability with the target probability. If the target model strongly agrees, the token is accepted. If it disagrees, the token is rejected and a new token is resampled from a corrected distribution that favors the target model’s probabilities while accounting for the draft’s proposal. This rejection-sampling step preserves the target model’s marginal distribution over generated text, so the method is not merely an approximation.

In practice, the speedup depends on how many draft tokens are accepted before a rejection, the relative cost of the draft and target models, and the efficiency of the target model’s parallel verification. A good draft model that matches the target model’s preferences on the task can accept long sequences, while a poor draft model causes frequent rejections and wastes compute. The two most common reasons the speedup is smaller than hoped are that the draft model is too weak or poorly aligned with the target model, and that the target model’s verification pass is not sufficiently cheaper than generating the same number of tokens sequentially."
