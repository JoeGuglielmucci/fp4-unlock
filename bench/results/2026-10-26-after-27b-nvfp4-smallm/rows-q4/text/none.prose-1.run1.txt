"Speculative decoding speeds up large language model inference by using a small, fast draft model to propose several future tokens before the large target model is run. The draft model generates a short candidate sequence, often greedily or with a simple sampling policy, because it is much cheaper to evaluate. The target model then processes the original prompt plus the proposed tokens in a single forward pass and computes its own probabilities for every position in that sequence. This lets the target model verify multiple candidate tokens at once instead of generating them one by one, which is the usual bottleneck in autoregressive decoding.

The key trick is a rejection test that preserves the target model’s output distribution. For each proposed token, the method compares the target probability with the draft probability. If the target model strongly agrees, the token is accepted. If it disagrees, the token is rejected and a new token is sampled from a corrected distribution that favors the target model’s probabilities while accounting for the draft’s proposal. This correction ensures that the final sequence is distributed exactly as if the target model had decoded normally, even though some tokens were produced by the draft.

In practice, speedup depends on how many draft tokens are accepted before a rejection, the relative cost of the draft and target models, batch size, and hardware efficiency. A small draft model can be fast, but if it is too weak or the prompt is hard, many proposals are rejected. If the target model is already highly parallelized or the batch is large, the benefit of verifying several tokens at once shrinks. The two most common reasons the speedup is smaller than hoped are low draft-target agreement and high target-model overhead from batching or hardware constraints."
