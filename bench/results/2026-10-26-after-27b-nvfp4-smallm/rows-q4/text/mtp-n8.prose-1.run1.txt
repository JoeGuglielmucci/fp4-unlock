"Speculative decoding speeds up large language model inference by using a smaller, faster draft model to propose several candidate tokens before the large target model is run. The draft model generates a short sequence, often called a draft, using its own autoregressive steps. The target model then processes the original prompt plus the draft in a single forward pass, computing logits for every position in that sequence. Because transformer attention lets the target model score all draft positions at once, it can verify multiple tokens with roughly the cost of one normal target-model step.

The key trick is rejection sampling. For each draft token, the target model’s probability is compared with the draft model’s probability. If the target model assigns enough probability to the token, it is accepted. If not, the token is rejected and a replacement is sampled from a corrected distribution that favors the target model’s probabilities. This correction ensures the final output distribution is exactly the same as if the target model had decoded alone, token by token. In other words, speculation only changes the order in which tokens are computed, not the probabilities from which they are drawn.

In practice, speedup depends on how often the target model accepts draft tokens, the relative cost of running the draft model versus the target model, and how many tokens are proposed per verification pass. A good draft model that is cheap and closely aligned with the target model can produce long accepted runs, reducing the number of expensive target passes.

The two most common reasons the speedup is smaller than hoped are low acceptance rates, often because the draft model is too small, poorly aligned, or the task is hard, and high overhead from running the draft model, memory transfers, or verification logic that eats into the savings."
