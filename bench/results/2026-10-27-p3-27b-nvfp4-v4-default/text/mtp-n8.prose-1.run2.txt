"Speculative decoding speeds up large language model inference by using a small, fast draft model to propose several future tokens, then checking them with the large target model in a single forward pass. In ordinary autoregressive decoding, the target model must generate one token at a time, so each token requires a full pass through the model and memory-bound operations. Speculative decoding changes this: the draft model greedily or stochastically samples a short sequence of candidate tokens, often using a smaller architecture, fewer layers, or a cached prefix. The target model then processes the original prompt plus all proposed tokens at once, computing logits for every position in that sequence. This lets it verify multiple candidates in parallel rather than sequentially.

The key correctness property is that the final output distribution can be identical to standard decoding from the target model. For each proposed token, the target model compares its probability with the draft model’s probability. If the target model is at least as confident, the token is accepted. If not, the token is rejected and a new token is resampled from a corrected distribution that favors the target model’s probabilities while accounting for the draft model’s proposal. This rejection-sampling step preserves the target model’s distribution exactly, so quality is unchanged.

In practice, speedup depends on how many draft tokens are accepted before a rejection, the cost of running the draft model, the overhead of the target model’s parallel verification pass, and hardware efficiency. Long accepted runs give large gains, while frequent rejections waste compute. The two most common reasons the speedup is smaller than hoped are a poor draft model that proposes tokens the target model often rejects, and high verification overhead or low hardware parallelism that makes checking several tokens only marginally cheaper than generating one."
