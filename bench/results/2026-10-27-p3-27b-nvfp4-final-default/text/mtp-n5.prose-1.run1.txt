"Speculative decoding speeds up large language model inference by using a small, fast draft model to propose several future tokens before the large target model is run. The draft model generates a short candidate sequence, often greedily or with a simple sampling policy, in a few cheap forward passes. The target model then processes the original prompt plus the proposed tokens in one forward pass, computing logits for every position in that sequence. This lets it verify multiple draft tokens at once instead of generating them one by one.

The key trick is a rejection-sampling correction. For each proposed token, the target model compares its probability for that token with the draft model’s probability. If the target model is at least as confident, the token is accepted. If not, the token is rejected and a new token is sampled from a distribution that favors the target model’s probabilities while removing the draft model’s mass. This correction guarantees that the final output distribution is exactly the same as if the target model had decoded alone, assuming the same random seed and numerical precision.

In practice, speedup depends on how many draft tokens are accepted before a rejection, the relative cost of the draft and target models, batch size, sequence length, and hardware efficiency. A good draft model that matches the target’s preferences and a short draft length can produce large gains, especially for single-request, latency-bound inference.

The two most common reasons the speedup is smaller than hoped are a low acceptance rate because the draft model is too small, poorly aligned, or the draft length is too long, and high overhead from running the draft model, extra memory, or inefficient batching that erases the savings from parallel verification."
