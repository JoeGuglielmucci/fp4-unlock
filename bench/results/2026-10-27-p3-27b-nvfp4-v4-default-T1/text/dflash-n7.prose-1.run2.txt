Speculative decoding speeds up LLM inference by using a small draft model to propose several future tokens, then a larger target model verifies them in a single forward pass. The draft model is cheap and fast, so it can generate a short candidate sequence, often with its own autoregressive steps or a small parallel decoder. The target model then processes the original prompt plus the draft tokens in one pass, computing logits for each position. Because the target model sees the full context, it can evaluate the probability of each proposed token and the next token after the draft sequence. Verification accepts or rejects tokens using a rejection-sampling rule: if the target distribution strongly agrees with the draft, the token is accepted; if not, it is rejected and a corrected token is sampled from a distribution that favors the target model’s probabilities. This correction step is what preserves the exact output distribution of ordinary target-model decoding, because every accepted or corrected token is sampled from the target model’s conditional distribution, not the draft model’s.

In practice, speedup depends on how many draft tokens are accepted before a rejection, the cost of running the draft model, the overhead of the target model’s verification pass, and hardware efficiency. If the draft model is too small or poorly aligned, acceptance rates fall. If the draft model is too large or the speculative length is too long, the extra computation cancels the benefit. The two most common reasons the speedup is smaller than hoped are low draft-target agreement, causing frequent rejections, and high overhead from the draft model or verification pass, especially when batch sizes, memory bandwidth, or implementation inefficiencies make the extra forward passes expensive.
