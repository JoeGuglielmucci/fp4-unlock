"Speculative decoding speeds up large language model inference by using a small, fast draft model to propose several future tokens before the large target model is run. The draft model generates a short sequence, often called a candidate or speculation, using its own cheap forward passes. The target model then processes the original prompt plus the proposed tokens in a single forward pass, computing logits at every position. Because the target model sees the whole candidate sequence at once, it can verify multiple positions in parallel rather than waiting for one token at a time.

The key correctness property is that the target model’s output distribution can be kept identical to ordinary autoregressive decoding. For each proposed token, the method compares the draft probability with the target probability. If the target model is confident enough, the token is accepted. If not, the token is rejected and a new token is sampled from a corrected distribution that favors the target model’s probabilities while avoiding double-counting the draft. This rejection-sampling step ensures the final sequence is drawn from the same distribution the target model would produce if it decoded alone.

In practice, speedup depends on how many draft tokens are accepted before a mismatch, the cost of running the draft model, the cost of the target verification pass, and hardware parallelism. A good draft model should be cheap and closely aligned with the target model. The verification pass must be efficient, and the batch size or sequence length should allow parallelism.

The two most common reasons the speedup is smaller than hoped are low acceptance rates, often because the draft model is too small, poorly aligned, or the task is hard, and overhead from the extra draft and verification passes, especially when few tokens are accepted or the target model is already fast."
