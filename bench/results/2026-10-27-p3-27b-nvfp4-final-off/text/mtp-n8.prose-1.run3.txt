"Speculative decoding speeds up large language model inference by using a small, fast draft model to propose several future tokens before the large target model is run. The draft model generates a short candidate sequence, often greedily or with a simple sampling policy, because it is much cheaper to evaluate. The target model then processes the original prompt plus the proposed tokens in a single forward pass. Since transformer inference is parallel over positions, that one pass yields logits for every position in the sequence, allowing the target model to score the draft tokens and also produce the next token distribution.

The key is rejection sampling. For each proposed token, the target model compares its probability with the draft model’s probability. If the target model’s probability is at least as high, the token is accepted. If it is lower, the token is rejected and a replacement is sampled from a corrected distribution that favors the target model’s probabilities. After the first rejected token, the remaining draft tokens are discarded. This correction guarantees that the final output distribution is exactly the same as if the target model had decoded one token at a time, assuming the same random seed and sampling parameters.

In practice, speedup depends on how many draft tokens are accepted before a rejection, the relative cost of the draft and target models, batch size, sequence length, and hardware efficiency. A good draft model that matches the target model’s preferences can accept multiple tokens, turning several sequential target steps into one. The two most common reasons the speedup is smaller than hoped are that the draft model is too weak or too different from the target model, causing frequent rejections, and that the target model’s forward pass is already cheap or the batch is large enough that the extra verification cost erases the benefit
