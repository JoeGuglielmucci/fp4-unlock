Imagine a graphics card as a very fast kitchen. The GPU is the chef, and the memory is the pantry. The chef can chop, mix, and plate dishes extremely quickly, but if the pantry is far away and the delivery cart can only carry a few ingredients at a time, the chef spends most of the time waiting for ingredients. That waiting is memory bandwidth: the rate at which data can move between memory and the GPU.

A game frame is made of millions of tiny pieces: colors, textures, depth, lighting, and so on. The GPU may be able to do trillions of math operations per second, but it still needs to read and write those pieces. If the memory bus is too narrow or too slow, the GPU runs out of work to do. This is called being memory-bound.

Here is a simple example. Suppose a GPU can compute 100 trillion operations per second. To draw one frame, it needs 200 trillion operations, so it could finish the math in 0.002 seconds, or 500 frames per second. But the frame also needs 2 gigabytes of data moved from memory. If the memory bandwidth is only 200 gigabytes per second, moving that data takes 2 / 200 = 0.01 seconds. That allows only 100 frames per second. The math is ready long before the data arrives, so the real limit is memory, not computation.
