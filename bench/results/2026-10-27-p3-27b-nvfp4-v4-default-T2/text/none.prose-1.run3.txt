"Speculative decoding speeds up large language model inference by using a small, fast draft model to propose several future tokens before the large target model is run. The draft model generates a short candidate sequence, often greedily or with a simple sampling policy, because it is cheap to evaluate. The target model then processes the original prompt plus the proposed tokens in a single forward pass and computes its own probabilities for every position in that sequence. This lets the target model verify multiple candidate tokens at once instead of generating them one by one, which is the usual bottleneck in autoregressive decoding.

The key trick is a rejection test that preserves the target model’s output distribution. For each proposed token, the method compares the draft probability with the target probability. If the target model is at least as confident as the draft, the token is accepted. If not, the token is rejected and a new token is sampled from a corrected distribution that favors the target model’s preferences while accounting for the draft’s proposal. Because this correction is derived from the target model’s probabilities, the final sequence has the same distribution as if the target model had decoded alone, assuming the same random seed and sampling settings.

In practice, speedup depends on how many draft tokens are accepted before a rejection, the relative cost of the draft and target models, batch size, and hardware efficiency. A good draft model that matches the target’s behavior can accept several tokens per target pass, reducing the number of expensive target calls. The two most common reasons the speedup is smaller than hoped are a poor draft-target mismatch, which causes frequent rejections, and high overhead from running the draft model or handling large batches, which erases the savings from fewer target passes."
